# P0-04 — CI GitHub Actions, Dependabot, protection de `main`

**Statut** : validé (2026-09-27 ; **D1 = dépôt rendu public** ; D5, D10 et D2–D13 acceptés, adaptés au dépôt public ci-dessous) · **Date** : 2026-09-27 · **Branche** : `chore/P0-04-ci` · Plan produit par l'agent `architect` (docs officielles GitHub, pnpm, Playwright ; `gh api` sur le dépôt).

## Objectif et critères d'acceptation
« CI GitHub Actions (`ci.yml`, `security.yml`), Dependabot, protection de branche `main`. *Accept.* : une PR factice déclenche tous les contrôles. »
Sur dépôt privé gratuit, protection de branche et rulesets renvoient 403 (vérifié). **Décision de l'utilisateur : rendre le dépôt public**, ce qui rend le critère réalisable tel quel (protection native gratuite).

## Approche
1. **`ci.yml`** : `pull_request` vers main, `push` sur main, `workflow_dispatch` ; `permissions: contents: read` ; `concurrency` (annulation des runs de PR remplacés, jamais sur main) ; `NEXT_TELEMETRY_DISABLED=1` ; actions **épinglées par SHA** ; `persist-credentials: false` ; aucun `pull_request_target`, aucun secret ; `timeout-minutes` partout.
   - `quality` : pnpm (version de `packageManager`) → Node (`.nvmrc`, cache pnpm) → `pnpm install --frozen-lockfile` → `pnpm verify`.
   - `e2e` : même préparation → `playwright install --with-deps --only-shell chromium` → `pnpm test:e2e` ; rapports en artefact si échec (7 jours).
   - `main-guard` (push sur main) : échoue si force-push ou si le commit ne vient d'aucune PR fusionnée (logique vérifiée : commit initial → 0 PR, commits de PR → 1).
2. **`security.yml`** : PR, push main, hebdomadaire, manuel. `gitleaks` (tout l'historique, binaire vérifié par SHA-256, valeurs masquées) ; `audit` (`pnpm audit --audit-level high`, prod + dev).
3. **`dependabot.yml`** : npm et actions, hebdomadaire (lundi 06:00 Bruxelles), délai de 3 jours (7 pour les majeures), groupes (vitest, next, react, playwright, mineures dev, mineures prod, actions), majeures ignorées avec raison (eslint, typescript, jsdom, @types/node, vite), préfixe `chore(deps)`.
4. Pousser la branche, ouvrir la PR P0-04 (déclenche les checks).
5. PR de démonstration rouge (D10), fermée et supprimée ensuite.
6. Documentation ; réglages Actions du dépôt (D5) ; contrôle du premier passage Dependabot.

Actions épinglées (vérifiées) : checkout v7.0.1 `3d3c42e5…`, setup-node v7.0.0 `82076278…`, pnpm/action-setup v6.1.0 `ea17c68d…`, upload-artifact v7.0.1 `043fb46d…`. gitleaks 8.30.1 linux x64 : SHA-256 `551f6fc8…70eb` (vérifié).
Consommation estimée : ~10 à 14 min par push de PR, ~1 100 à 1 300 min/mois sur 2 000 (à mesurer).

## Tests prévus
- **Statiques** : `pnpm format:check` (YAML), toutes les actions épinglées par SHA, aucun `pull_request_target` ni `secrets.`, `persist-credentials: false` et `timeout-minutes` partout ; logique `main-guard` rejouée.
- **Nominal** : sur la PR P0-04, `quality`, `e2e`, `gitleaks`, `audit` verts ; `main-guard` ignoré ; permissions en lecture ; aucun secret dans les journaux.
- **Négatifs** (PR jetable, jamais fusionnée) : `any` → `quality` rouge ; `lang="en"` → `e2e` rouge avec rapport ; faux jeton `ghp_` aléatoire et invalide → `gitleaks` rouge, valeur masquée ; test unitaire rouge → `quality` rouge ; deux pushes rapprochés → premier run annulé. Puis fermeture et suppression de la branche.
- **Dependabot** (après fusion) : exécution réussie, PR regroupées, CI verte.

## Décisions à valider
- **D1 — Protection de `main`** : (A) rester privé et gratuit : pre-push local + `guard-bash` + contrôle a posteriori `main-guard` (recommandé) ; (B) GitHub Pro (payant) : vraie protection, checks requis ; (C) dépôt public : tout gratuit (protection, CodeQL, secret scanning) mais code, prompts et plans publics.
- **D2** : CodeQL indisponible, retiré des docs ; contrôles compensatoires (ESLint typé, revues) ; Semgrep à réévaluer en P1-02.
- **D3** : binaire gitleaks MIT vérifié plutôt que l'action sous licence propriétaire.
- **D4** : job `main-guard` (détecte, n'empêche pas).
- **D5** : réglages Actions du dépôt : SHA obligatoire, actions autorisées limitées (GitHub + pnpm/action-setup).
- **D6** : pas de cache des navigateurs.
- **D7** : CI complète aussi sur push `main`.
- **D8** : `pnpm audit --audit-level high` bloquant en PR (dev compris).
- **D9** : configuration Dependabot ci-dessus.
- **D10** : PR de démonstration rouge (pushes, ouverture, fermeture ; faux jeton factice laissé dans `refs/pull/<n>` sur GitHub ; ~30-40 min de CI).
- **D11** : ADR 0009 + correction ADR 0004/0008.
- **D12** : vérification ponctuelle des workflows par zizmor (`uvx`, téléchargement PyPI).
- **D13** : DoD de `CLAUDE.md` (« checks CI verts sur la PR ») et `gitleaks git` dans les skills.

## Risques
