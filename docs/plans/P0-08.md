## 1. Objectif, critères, périmètre

**ROADMAP, ligne 23.** Le bac à sable Bash doit devenir la **frontière réelle** des secrets locaux. Les hooks de P0-07 restent le filet.

**Critères d'acceptation :**
1. Lire `.env.local` depuis Bash échoue, directement ou par un sous-processus (`node -e`).
2. `pnpm build`, `test:e2e`, `pnpm install`, `git push` et `gh` fonctionnent, mesures à l'appui.
3. Le plan tranche comment `pnpm dev` lancé par Claude obtient ses variables.

**Dans le périmètre :**
- le bloc `sandbox` et une variable `env` dans `.claude/settings.json` ;
- un script de sondes `scripts/test-sandbox.sh` ;
- le confinement des hooks qui exécutent du code du dépôt (Q2) ;
- les mesures ;
- la documentation (ADR 0011, SECURITY, TESTING, ROADMAP, une ligne de CLAUDE.md selon Q7).

**Hors périmètre :**

- clés API pour l'éval (P3) ;

Sources : docs `code.claude.com` (sandboxing, settings-reference), source de `anthropic-experimental/sandbox-runtime` (profil macOS), `node_modules`.

1. **Deux versions de Claude Code sur le poste.**

2. **`autoAllowBashIfSandboxed` vaut `true` par défaut.**

## 6. Le point dur : d'où viennent les variables

`denyRead` empêche Next, Vite/Vitest et Playwright lancés par Claude de lire `.env.local`. Aujourd'hui, **rien n'en a besoin** (§2, point 7).

**Option A — recommandée.** Aucun secret dans le bac à sable ; un serveur avec de vrais secrets est lancé par l'utilisateur dans son terminal.
- `pnpm dev`, `build`, `test` et `test:e2e` lancés par Claude tournent **sans `.env.local`**, avec les défauts non secrets de `src/lib/env.ts` et les variables non secrètes injectées :
  - E2E : `webServer.env` existe déjà ;
  - ponctuellement : `VAR=valeur pnpm dev` ;
  - globalement : bloc `env` de `settings.json`.
- Next journalise un `Failed to load env … EPERM` : c'est attendu, sans contenu.
- Quand l'utilisateur a besoin du vrai `.env.local`, il lance lui-même `pnpm dev` **dans son terminal**. Pas via `!` : le mode `!` s'exécute hors bac à sable **et** renvoie la sortie dans la conversation. Claude interroge ce serveur par `http://localhost:3000` (sortie localhost permise).
- Avantages : la frontière est simple et prouvable ; identique à la CI ; aucun outil nouveau.
- Risques : friction quand de vrais secrets seront requis (à partir de P1-01) ; l'utilisateur exécute alors du code écrit par Claude hors bac à sable, d'où « relire `git diff` avant de lancer ».

**Option B — valeurs de dev non secrètes injectées par un script** (ex. `node --env-file=<fichier non nommé .env*> …`).
- Utile à partir de P1-01 avec un **Postgres local** (identifiants jetables, `localhost` permis) et un `BETTER_AUTH_SECRET` de dev généré par le script, pas commité (gitleaks, `litteraux-secrets`).
- Le fichier ne peut pas s'appeler `.env*` : le motif est refusé en lecture, et Next ne chargerait pas un autre nom de toute façon.
- **À décider en P1-01, pas ici.**

**Option C — `excludedCommands: ["pnpm dev"]` : rejetée.**
- `pnpm dev` exécuterait hors bac à sable du code que Claude modifie (`next.config.ts`, `src/**`). Un `next.config.ts` piégé copierait `.env.local` dans `public/`, et la frontière disparaîtrait.
- `Bash(pnpm dev)` est en allow : cela partirait sans demande.
- Il n'existe aucun verrou « géré » sur cette liste.

**Option D — injection par la variable d'environnement du processus Claude : rejetée.** Les commandes confinées héritent de l'environnement : `node -p process.env` suffirait.
- Pour les **clés d'API HTTP** (P3 : Anthropic ; P2 : Adzuna…), la bonne piste est `sandbox.credentials.envVars` en `mask` avec `injectHosts`. C'est un réglage **utilisateur** qui exige `tlsTerminate` : la commande ne voit qu'un leurre, le proxy substitue la vraie clé à la sortie.
- Inutilisable pour `DATABASE_URL` : le protocole Postgres n'est pas du HTTP.

**Décision proposée :** A maintenant. B tranchée en P1-01. `mask` étudié en P3.

**`pnpm test` et `pnpm verify` sans `.env.local` :** oui, prouvé par le job `quality` de la CI. Dans le bac à sable, deux conditions à mesurer :
- l'exception `.env.example` (lue par deux tests) ;
- le chemin `stat` en EPERM de Vite.

**La CI ne change pas** : pas de Claude, pas de `.env.local`, variables fournies par le workflow.

## 7. Hooks, permissions, sous-agents

- **Frontière et filet.** Le hook reste le filet : il refuse plus tôt, avec un message clair, et couvre aussi Read, Grep et Edit. Le bac à sable est la frontière OS pour Bash et tous ses descendants.
- **Les sondes passent par un script.** `guard-bash` refuse tout texte de commande qui nomme le fichier canari. Le script `scripts/test-sandbox.sh` construit les noms à l'intérieur : le hook voit `bash scripts/test-sandbox.sh`, et c'est bien le bac à sable qui est mesuré.
- **`allowUnsandboxedCommands: false`** : le paramètre `dangerouslyDisableSandbox` est ignoré. Une commande bloquée échoue, sans nouvelle tentative hors bac à sable. Claude demande alors à l'utilisateur de la lancer dans son terminal (ligne CLAUDE.md, Q7).
- **`autoAllowBashIfSandboxed: false`** (Q3) : les listes `allow`/`ask` actuelles gardent leur sens. `git push`, `pnpm install`, `gh pr create` et `docker` restent demandés, et toute commande non listée aussi. Le bac à sable ne sert pas à supprimer des demandes ici.
- **`excludedCommands` vide.** Une commande exclue tourne avec tous les droits, et elle peut exécuter du code du dépôt :
  - `git push` exécute `.githooks/pre-push` ;
  - `pnpm` exécute les scripts ;
  - `gh` peut lire un fichier par son nom.
  C'est une commodité, pas une frontière (doc).
- **`denyWrite ./.githooks`** : un hook git piégé s'exécuterait hors bac à sable au prochain push de l'utilisateur, sans action consciente de sa part.
- **Sous-agents** : même processus, même bac à sable (doc). Le signalement « Credential Exploration » devient impossible au niveau de l'OS.
- **Hooks Claude (Q2)** : ils tournent hors bac à sable. `confine` les enveloppe avec `sandbox-exec -p <profil>`. Lignes clés du profil (dernière règle gagnante) :

  ```
  (version 1)(allow default)
  (deny file-read* file-write* (regex #"^<RACINE échappée>/\.[eE][nN][vV]"))
  (allow file-read* (literal "<RACINE>/.env.example"))
  ```

  Sans `sandbox-exec` sur macOS, `confine` n'exécute rien et avertit : la vérification est perdue, mais le secret reste fermé. Hors macOS (CI), la commande est exécutée telle quelle.

## 8. Tests et mesures d'acceptation (écrits avant la configuration)

### `scripts/test-sandbox.sh [bash|hooks]`

Codes de sortie : 0 = tout confiné ; 1 = une sonde a lu ; 3 = bac à sable inactif ; 4 = `confine` indisponible.

**Garde d'entrée.**
- En mode `bash`, le script vérifie que le bac à sable est actif (`sandbox_check` = 1 **et** `SANDBOX_RUNTIME=1`). Sinon il sort avec le code 3 **sans lancer aucune sonde de lecture**.
- En mode `hooks`, lancé par l'utilisateur dans son terminal, chaque sonde passe par `confine`.

**Canari.**
- Fichier canari `.env.canary`, ignoré par git via `.env*`, contenant `TROUVIO_CANARI=canari-p0-08-pas-un-secret`.
- Le script le crée s'il manque : c'est une écriture, permise.
- Si la création est refusée, il affiche la commande à lancer dans le terminal.
- Il reste en place comme fixture.

**Règle de sortie.** Toute sortie de sonde est capturée puis cherchée pour le marqueur `canari-p0-08`, **jamais affichée**. `.env.local` n'est testé que par son code de retour, stdout et stderr vers `/dev/null`. Le script affiche une ligne `OK`/`ÉCHEC <libellé>` par sonde.

**Lecture du canari : chaque sonde doit échouer.**
- `cat` direct ;
- `node -e "require('fs').readFileSync(process.argv[1])"` ;
- `python3 open()` ;
- `grep -r` limité au premier niveau hors `node_modules` et `.git` ;
- `find … -exec cat` ;
- lien symbolique dans `$TMPDIR` ;
- **lien physique** dans `$TMPDIR` et dans le dépôt ;
- `cp` ;
- `mv` vers un nom neutre (doit échouer ; sinon restauration et ÉCHEC) ;
- `tar c | tar xO` ;
- `git hash-object` ;
- `git diff --no-index` ;
- `sqlite3 readfile()` ;
- **nom en majuscules** (`.ENV.CANARY`).

**`.env.local` : même série en code de retour seul.** Au minimum : `cat`, `node -e` et `python3`.

**Contre-épreuves, qui doivent réussir :**
- lecture de `.env.example` ;
- écriture et lecture d'un fichier ordinaire du dépôt ;
- `curl` par le proxy vers `https://registry.npmjs.org/` (code 200).

**Confinement réel, qui doit échouer :**
- `touch ~/.trouvio-sonde-p008` ;
- `: >> .env.local` (ouverture en ajout, n'écrit rien) ;
- écriture dans `.githooks/` ;
- connexion directe `curl --noproxy '*' https://github.com`.

### Comment on sait que le bac à sable est actif

1. **Preuve noyau** : `python3 -c 'import ctypes,os;print(ctypes.CDLL(None).sandbox_check(os.getpid(),None,0))'` affiche `1`. Constaté `0` aujourd'hui hors bac à sable.
2. `SANDBOX_RUNTIME=1` et `TMPDIR` changé.
3. Les écritures hors dépôt et les connexions directes sont refusées, avec un rapport de violation dans le résultat.
4. Dans la CLI du terminal : `/sandbox` → onglet Config (configuration résolue et chemins protégés) ; `claude doctor` sans avertissement de bac à sable.
5. Aucune demande intitulée « Bash command (unsandboxed) » pendant toute la tâche.

## 9. Risques et retour arrière

- **Versions** : la CLI 2.1.42 ignore ou applique autrement certaines clés. La mettre à jour avant toute mesure (Q8). Les mesures valent pour la version notée.
- **Chromium sous Seatbelt** (Mach, GPU) : c'est le poste le plus incertain. On élargit au nom près, jamais avec `"*"`.
- **`gh` et TLS** : `enableWeakerNetworkIsolation` ouvre `trustd` (fuite possible par AIA/OCSP). Accepté, car les secrets du projet sont illisibles. Exclure `gh` est rejeté (§7).
- **`.git/config` protégé** : `push -u`, `branch --set-upstream-to` et `prepare` échouent en écriture. Repli : `git push origin HEAD`, amont posé une fois par l'utilisateur.
- **pnpm** : une montée de `packageManager` (Dependabot) déclenche un téléchargement vers `~/Library/pnpm/.tools`, refusé. `playwright install` est aussi refusé. Les deux sont à lancer par l'utilisateur.
- **`allowLocalBinding`** : sortie vers tout port localhost, donc services locaux joignables (Herd, un port de débogage de Chrome ouvert, Docker en TCP). Ne pas laisser de port de débogage ouvert.
- **Trousseau** (`SecurityServer`) : le jeton `gh` et les éléments créés par `security` restent lisibles par du code confiné. Filet par la Q5 ; recommandation : jeton `gh` à grain fin limité à ce dépôt.
- **Domaines WebFetch fusionnés** (sites sur Vercel, par exemple) : le proxy ne regarde pas le TLS, donc une façade de domaine (domain fronting) est possible. Résiduel accepté : `.env*` est illisible, et les secrets de `$HOME` sont couverts par la Q4.
- **Liens physiques** : si la sonde lit, c'est un trou dans `sandbox-runtime`. À signaler en amont, documenter le résiduel ; le hook reste le filet.
- **Code exécuté ensuite par l'utilisateur hors bac à sable** (`pnpm dev` dans son terminal, scripts) : le bac à sable ne protège pas contre ce cas. Règle : relire `git diff` avant.
- **`failIfUnavailable`** : si le bac à sable ne démarre pas, Claude Code refuse de démarrer.
- **`sandbox-exec` déprécié** : `confine` échoue sans rien exécuter (§7).
- **Performance** : surcoût annoncé minime ; le tableau du §8 le chiffrera.
- **Journal EPERM de Next** : bruit attendu, pas une erreur.

**Retour arrière :**
- Revenir sur le commit de `settings.json`.
- Pour une seule session, par l'utilisateur uniquement : `claude --settings '{"sandbox":{"enabled":false}}'` ou `CLAUDE_CODE_SANDBOX_ENABLED` (doc). Le drapeau l'emporte sur le réglage du projet.
- Q2 : revenir sur `lib.sh`, `format.sh` et `stop-verify.sh`.

## 10. Questions ouvertes (avec recommandation)

- **Q1 — Variables de `pnpm dev`** : option A maintenant (aucun secret confiné, serveur avec secrets lancé dans le terminal de l'utilisateur), B tranchée en P1-01, `mask` en P3. **Recommandé : A.**
- **Q2 — Confiner les hooks** `format.sh` et `stop-verify.sh` par `sandbox-exec` **dans cette tâche**. Sans cela, la frontière est contournable par un test ou une config modifiée. **Recommandé : oui.** Alternative : une tâche P0-09 dédiée.
- **Q3 — `autoAllowBashIfSandboxed: false`.** **Recommandé : oui.** Avec `true`, `gh gist create`, `gh api` ou `curl` partiraient sans demande.
- **Q4 — `denyRead` sur `~/.ssh`, `~/.aws`, `~/.docker`, `~/.netrc`.** **Recommandé : oui**, après avoir mesuré qu'aucune commande ne casse. Remote en HTTPS, pas de signature SSH configurée.
- **Q5 — Filet `guard-bash`** : refuser `gh auth token`, `security find-*-password` et `dump-keychain`. **Recommandé : oui.** Hors tâche : passer `gh` sur un jeton à grain fin.
- **Q6 — `gh`** : `enableWeakerNetworkIsolation` seulement si la mesure l'exige. **Recommandé.** Rejeté : `excludedCommands` pour `gh`.
- **Q7 — ADR 0011 + une ligne dans CLAUDE.md §6.** **Recommandé : oui.** La décision engage P1, P3 et P10.
- **Q8 — Mettre à jour la CLI du terminal** (2.1.42) avant les mesures. **Requis.**
- **Q9 — `failIfUnavailable: true`.** **Recommandé : oui.** Mieux vaut ne pas démarrer que tourner sans frontière.

### Décisions (2026-09-30)

L'utilisateur a délégué le choix à Claude. Toutes les recommandations sont retenues :
- **Q1** : option A. Aucun secret dans le bac à sable ; un serveur avec de vrais secrets est lancé par l'utilisateur dans son terminal. B sera tranchée en P1-01, `mask` étudié en P3.
- **Q2** : confinement des hooks **dans cette tâche**. Sans lui, la frontière n'existe pas vraiment. Si `sandbox-exec` bloque, on s'arrête et on consulte l'utilisateur plutôt que de repousser en silence à une P0-09.
- **Q3** : `autoAllowBashIfSandboxed: false`.
- **Q4** : `denyRead` sur `~/.ssh`, `~/.aws`, `~/.docker`, `~/.netrc`, maintenu seulement si les mesures du §8 ne cassent rien.
- **Q5** : ajout au filet `guard-bash`.
- **Q6** : `enableWeakerNetworkIsolation` seulement si la mesure l'exige ; `gh` jamais exclu.
- **Q7** : ADR 0011 et une ligne dans CLAUDE.md §6.
- **Q8** : l'utilisateur met à jour la CLI du terminal avant l'étape 2 ; bloquant.
- **Q9** : `failIfUnavailable: true`, sortie de secours documentée au §9.

## 11. Étapes d'implémentation (chacune vérifiable)

1. **Branche et version.** Créer la branche. L'utilisateur met à jour la CLI ; noter les versions de l'app et de la CLI.
2. **Références hors bac à sable.** Mesurer `pnpm test`, `pnpm build`, `pnpm test:e2e`, `pnpm install --frozen-lockfile` : durées et codes.
3. **Script des sondes (tests d'abord).** Écrire `scripts/test-sandbox.sh`, puis le lancer. Attendu : sortie 3 « inactif », rouge.
4. **Filet `guard-bash` (Q5).** Cas `test-hooks.sh` rouges, puis `guard-bash.sh`, puis vert.
5. **Confinement des hooks (Q2).** `confine` dans `lib.sh`, puis `bash scripts/test-sandbox.sh hooks` lancé par l'utilisateur, rouge. Brancher ensuite `format.sh` et `stop-verify.sh`, et relancer : vert.
6. **Réglages.** Modifier `.claude/settings.json` (confirmation humaine) et valider avec `jq empty .claude/settings.json`. **Nouvelle session**, car `enabled` est lu au démarrage.
7. **Activation.** `bash scripts/test-sandbox.sh` (mode `bash`) : vert, preuve noyau comprise.
8. **Mesures du §8** dans cet ordre : test/verify, build, E2E, dev, install, push, gh. Chaque élargissement (Mach, `enableWeakerNetworkIsolation`, écriture, domaine) est justifié par la violation relevée et consigné.
9. **Même contrôle dans la CLI du terminal** : `claude doctor` et `/sandbox` → Config.
10. **Documentation** : ADR 0011, SECURITY.md, TESTING.md, CLAUDE.md (Q7), ROADMAP (case et note P1-01), section « Réalisé » avec le tableau de mesures.
