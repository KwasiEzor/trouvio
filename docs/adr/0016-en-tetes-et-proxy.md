# ADR 0016 — En-têtes de sécurité, CSP à nonce et rôle de `proxy.ts`
**Statut** : accepté · **Date** : 2026-10 · Plan : `docs/plans/P1-05.md` · Complète les ADR 0013, 0014 et 0015.

## Contexte
SECURITY §3 exige une CSP sans `unsafe-inline` pour les scripts, HSTS, `nosniff`, `Referrer-Policy`, `Permissions-Policy` et `frame-ancestors 'none'`. Les scripts que Next injecte (bundles, charge RSC en ligne) ne peuvent être autorisés sans `unsafe-inline` que par un nonce, que Next 16.3.8 lit dans l'en-tête de **requête** `content-security-policy` ; une page prérendue n'en a pas, et ses scripts seraient bloqués. Par ailleurs, la session n'était pas glissante (ADR 0013, décision 13) : seul un Server Component la lisait, et il ne peut pas réécrire le cookie (Better Auth avale l'exception de `cookies().set`), d'où une déconnexion 7 jours après la connexion. Enfin, `/api/auth/get-session` rendait `session.token` en JSON, et `/sign-in/email` et `/magic-link/verify` rendaient `token`.

## Décision
1. **Deux sources d'en-têtes, sans chevauchement** (`src/lib/http/security-headers.ts`, pur) :
   - `next.config.ts` `headers()`, sur toutes les routes (pages, API, `_next/static`, `public/`) : `Strict-Transport-Security: max-age=63072000; includeSubDomains` (sans `preload`, P10-02), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (accéléromètre, caméra, capture d'écran, géolocalisation, gyroscope, magnétomètre, micro, MIDI, paiement, série, USB coupés), `X-Frame-Options: DENY` ; sur `/api/*`, une CSP qui n'autorise rien (`default-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`) ;
   - chemins hors du proxy autres que l'API (`/_next/static/*`, `/_next/image`, `/icon.svg`, `/brand/*`, et leurs 404) : CSP stricte sans nonce, `default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` (un SVG ouvert directement n'exécute rien) ; un test fige l'absence de chevauchement avec le matcher ;
   - `src/proxy.ts`, pages seulement (matcher : tout sauf `api/`, `_next/static/`, `_next/image`, `/icon.svg`, `brand/` ; les prefetchs ne sont pas exclus, l'en-tête étant forgeable) : CSP à nonce, `x-request-id`, prolongation de session.
2. **CSP des pages** : `default-src 'self'` ; `script-src 'self' 'nonce-…' 'strict-dynamic'` (+ `'unsafe-eval'` en développement seulement) ; `style-src 'self' 'nonce-…'` (développement : `'unsafe-inline'`, overlay de Next) ; `style-src-attr 'unsafe-inline'` (attributs `style` de `next/image`, Magic UI, `motion`) ; `img-src 'self' data: blob:` ; `font-src 'self'` ; `connect-src 'self'` + l'origine exacte d'ingestion Sentry ; `object-src 'none'` ; `base-uri 'none'` ; `form-action 'self'` ; `frame-ancestors 'none'` ; `upgrade-insecure-requests` si `APP_URL` est en https. Nonce : 16 octets aléatoires par requête, refusé s'il sort du motif base64 (pas d'injection de directive).
3. **Toutes les pages sont rendues à la requête** : `await connection()` dans `src/app/layout.tsx`, en un seul point. PPR et pages statiques sont exclus tant que la CSP est à nonce.
4. **Sentry** : `connect-src` reçoit l'origine `https://o<id>.ingest.de.sentry.io` tirée du DSN figé au build (`publicSentryConfig`, valeur du bundle navigateur ; sa présence dans le bundle du proxy a été vérifiée au build). Jamais de joker `*.ingest.de.sentry.io` (exfiltration vers toute organisation). Pas de `tunnelRoute`.
5. **Rôle de `proxy.ts`** (précise l'ADR 0014) : il ne décide **jamais** d'un accès. Il lit la session en base (`auth.api.getSession` en processus, `src/lib/auth/session-refresh.ts`) sur un chargement de document (GET ou HEAD, `sec-fetch-dest` « document » ou absent) porteur d'un cookie de session, et recopie le `Set-Cookie` produit : cookie prolongé au plus une fois par jour, ou cookie d'effacement d'une session expirée. Dans le runtime Next, l'adaptateur remplace cette recopie par les cookies posés par `nextCookies` (même contenu, une seule ligne, vérifié en E2E). Une réponse qui prolonge reçoit `Cache-Control: private, no-store`. Une panne de lecture est journalisée (`warn`, une fois par 10 minutes, avec le `requestId`) puis ignorée : la page échoue fermé d'elle-même (`requireUser`). Les navigations RSC et les prefetchs ne déclenchent rien. Rien n'est lu à l'import (câblage paresseux).
6. **`/get-session` fermée** (`DISABLED_PATHS`, précise l'ADR 0015) : aucun consommateur ; la session se lit côté serveur (`auth.api.getSession`, non concerné par `disabledPaths`). ESLint interdit `authClient.useSession` et `authClient.getSession`. Un hook `after` (`src/lib/auth/session-token-hook.ts`) met `token` à `null` et retire `session.token` de **toute** réponse JSON, sans liste de chemins : une route rouverte (`/change-password`, P7-02), un plugin ou une montée de version restent couverts. La garde ESLint se contourne par alias : le contrôle effectif est `disabledPaths`.
7. **`requestId`** : UUID généré par le proxy, qui écrase la valeur du client, transmis en en-tête de requête et renvoyé en réponse ; `requestLogger()` (`src/lib/http/request-context.ts`) rend `logger.child({ requestId })` ; `x-request-id` est un en-tête autorisé dans Sentry, seulement s'il est un UUID. Hors des pages (`/api/*`, hors matcher), la valeur vient du client : validée, mais seulement indicative ; les futures routes applicatives (P5, P6) généreront la leur.
8. **Page 404 propre** (`src/app/not-found.tsx`) : celle de Next injecte un `<style>` en ligne sans nonce, bloqué par la CSP.
9. **« Déjà connecté »** : `redirectIfSignedIn()` (`guards.ts`) en première ligne de `/connexion` et `/inscription`, décidé par `decideAccess` (une session refusée reste sur la page : pas de boucle avec `requireUser`). Jamais dans le proxy.

## Conséquences
- \+ Aucun script autorisé par `unsafe-inline`, en production comme en développement ; un script en ligne injecté ne s'exécute pas (E2E).
- \+ Sessions réellement glissantes : 7 jours depuis la dernière visite, et non depuis la connexion (complète la décision 13 de l'ADR 0013), prouvé en intégration et en E2E.
- \+ Ni jeton de session en JSON, ni écriture dans `rate_limits` pour lire ou prolonger une session (la note de l'ADR 0015 sur `/get-session` est levée).
- − Toutes les pages sont dynamiques : pas de cache HTML, TTFB plus long (mesure Lighthouse en P7-01 ; volume faible, pas de CDN, ADR 0006).
- − Une lecture de session en base de plus par chargement de page connecté (par clé primaire).
- − Un onglet resté ouvert plus de 7 jours sans rechargement complet est déconnecté (aucune prolongation en navigation RSC).
- − Un composant qui injecte un élément `<style>` (Radix Dialog, `react-remove-scroll`) ou un script tiers (Stripe) devra recevoir le nonce (`x-nonce`, `setNonce`) ou une origine dans la CSP : notes P6, P7-01, P9.
- − Le DSN Sentry doit être identique au build et à l'exécution (note P10-02) ; les violations CSP ne sont pas encore remontées (`report-to`, P10-02).
- − La recopie des cookies dépend de l'adaptateur Next et de `nextCookies` : une montée de version se vérifie par l'E2E `tests/e2e/session.spec.ts`.
- − La doc de Next cite `unstable_doesProxyMatch`, absent de 16.3.8 : les tests utilisent `unstable_doesMiddlewareMatch`.

## Alternatives écartées
- **Tout faire dans le proxy** : les fichiers statiques perdraient `nosniff` et HSTS, et le proxy tournerait devant chaque `/api/auth/*`.
- **`style-src 'unsafe-inline'`** : relâcherait aussi les éléments `<style>` ; **CSP de style stricte** : casse `next/image` et Magic UI.
- **SRI expérimentale de Next** : ne couvre pas les scripts en ligne de Next. **Sans nonce** : imposerait `unsafe-inline`.
- **Relayer `/api/auth/get-session` en HTTP depuis le proxy** : saut réseau, limiteur, IP du serveur. **`authClient.getSession()` côté client** : JavaScript requis, jeton exposé, écriture `rate_limits` à chaque page.
- **`tunnelRoute` Sentry** : trafic serveur et route publique, utiles seulement contre les bloqueurs de publicité. **Joker Sentry** : exfiltration.
- **Redirection « déjà connecté » dans le proxy** : décider d'un accès sur la seule présence d'un cookie, avec risque de boucle.
